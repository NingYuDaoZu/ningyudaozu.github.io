这个博客是怎么搭起来的

2026 年 10 月 7 日 约 7 分钟 前端 · 折腾记录

我有一个 GitHub Pages 仓库，一直空着。前几天终于决定把它变成一个博客， 然后花了大概一个晚上把整个站点写完了。这篇记录一下方案选择的过程，以及最后落地的样子。

需求是什么

动手之前，我先把自己的需求列了一遍——这一步很重要，因为它直接决定了后面不做什么：

  • 能长期维护。三年后我回来写，不应该还需要先升级依赖。
  • 部署零成本。不买服务器，不配 CI，推上去就能访问。
  • 写起来不费劲。重点是内容，不是折腾工具链。
  • 打开够快。最好首屏一个 RTT 就完事。
  • 长得像样。排版要舒服，手机上也要好看。

注意这里面没有「支持 Markdown 写作」「支持标签自动生成」「支持评论系统」这类需求。 一开始我也以为自己需要，后来发现那都是工具强加给我的想象。

候选方案

主流的路子大概三条，我逐个试了一遍：

方案 优点 代价 结论
Jekyll GitHub Pages 原生支持，写 Markdown，主题多 依赖 Ruby；主题改起来要读 Liquid；构建偶尔莫名其妙失败 能用，但不够透明
Hexo / Hugo / Astro 生态成熟，主题漂亮，Markdown 工作流舒服 需要本地或 CI 构建；依赖会过期；换主题等于重来一次 对这个体量来说太重了
纯静态 HTML 零依赖、零构建、完全可控、永不过期 每篇文章都是 HTML；列表页要手动更新 最后选了它

前两条路我都走过。Hexo 尤其典型：装完 node_modules 有 200MB， 但真正属于我的内容不到 50KB。半年后回来，npm install 先报三个安全警告， 然后主题的某个插件不兼容新版 Node……我意识到，我维护的不是博客，是一个前端项目。

为什么纯静态反而是对的

博客这个东西有个特点：它几乎永远是读的，很少是写的。

一个博客的生命周期里，「被访问」的次数是「被编辑」次数的一万倍以上。 为一个万分之一频率的操作引入构建系统，是典型的本末倒置。

而纯静态 HTML 在「读」这件事上几乎无可挑剔：

  1. 浏览器直接渲染，没有水合、没有打包、没有请求瀑布。
  2. CDN 就能缓存，断网了只要打开过一次还能看。
  3. 它不会因为某个依赖被作者删掉而突然白屏。

静态网页是互联网上最长寿的内容格式。二十年前写的 HTML，今天浏览器还能渲染； 但二十年前的 package.json，今天连安装都装不上。

目录结构

整个站点长这样，一目了然：

blog/
├── index.html            # 首页
├── archive.html          # 归档
├── about.html            # 关于
├── 404.html              # 404 页面
├── feed.xml              # RSS 订阅
├── sitemap.xml           # 站点地图
├── robots.txt
├── .nojekyll             # 告诉 GitHub Pages 别用 Jekyll 处理
├── assets/
│   ├── css/style.css     # 全站样式（含深浅色主题）
│   ├── js/main.js        # 主题切换 + 代码复制
│   └── img/
└── posts/
    └── hello-world.html  # 一篇文章 = 一个 HTML 文件

没有 node_modules，没有 package.json，没有 config.yml。 整个站点加起来不到 100KB，用记事本都能改。

关于 .nojekyll

这个空文件值得单独说一下。GitHub Pages 默认会对仓库跑一遍 Jekyll， 而 Jekyll 会忽略所有下划线开头的文件和目录。加上 .nojekyll 之后，GitHub 就把文件原样输出，既省掉构建时间，也避免莫名其妙的构建报错。

几个值得记录的小细节

深浅色主题，而且不闪白

主题跟随系统，也可以手动切换，选择存在 localStorage 里。 关键是要在 <head> 里用一段内联脚本提前设置 data-theme， 否则深色模式下每次打开都会先闪一下白： 

<script>
  (function () {
    try {
      var t = localStorage.getItem("blog-theme");
      if (t) document.documentElement.setAttribute("data-theme", t);
    } catch (e) {}
  })();
</script>

不加载任何外部字体

中文网页最沉重的资源就是字体，一个思源宋体动辄 5MB+。 这里直接用系统字体栈：PingFang SC / Microsoft YaHei / Noto Sans SC 依次回退。不同系统上观感略有差异，但换来的是秒开。

没有统计脚本

一开始我准备加个访问量统计，后来放弃了。加了就得处理 Cookie 提示、隐私政策， 而我其实也并不真的需要那几个数字。不收集，就是最好的隐私保护。

怎么部署

如果你也想这样搭一个，步骤短到可以写在一条列表里：

  1. 在 GitHub 新建一个仓库，命名为 <你的用户名>.github.io。
  2. 把站点文件推到这个仓库的根目录。
  3. 仓库的 Settings → Pages 里，把 Source 设为 main 分支根目录。
  4. 等一分钟，访问 https://<你的用户名>.github.io。
新文章怎么加

复制 posts/ 下任意一篇文章，改文件名和正文，再把首页和归档页里的列表 一行加进去就行，不依赖任何额外工具。

写在最后

折腾完回头看，这个方案其实一点都不「高级」。没有 SSG，没有 Islands 架构， 没有一行 TypeScript。它唯一的优点是五年后我还能看懂它、改得动它。

而对于一个博客来说，我觉得这已经是最重要的优点了。工具会过时，写下来的东西不会。
